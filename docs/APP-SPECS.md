# App specs — basic-apps

## Content

- The page shows the folder tree of one workspace: one card per folder with its role,
  a sentence of prose, the number of entries and their names.
- `secrets/` and `backups/` show **existence only** — no file names, no contents.
- The project table shows each repository under `repos/` with app version, pinned
  standard version, deviation count, last commit date and the restore state:
  `repos.txt` (restore.sh clones it), `local only` (deliberately not in the registry)
  or `not restored`.
- `All` and `Publishable` filter the folder cards; the mode lives in the address.
- Drift is listed, never hidden: a folder without a description, a description without
  a folder, a repository that restore.sh would not clone, a `localOnly` repository that
  is in the registry anyway.
- `Origin` means an `origin` remote is configured in the local git config. It does not
  mean the repository answers on GitHub.

## Data

- The page reads `site/state.json`. It is generated by `tools/scan.py` on the machine it
  describes and committed with the change.
- The scanner writes nothing when the document would contain an address, a volume path,
  an ssh key path, a private key or a token. `secrets/` and `backups/` are never read.
- CI can only run `--check`: shape, required fields, no sensitive text, no drift in the
  committed file. It cannot prove the file is current — only a local scan can.
- **Deviation `BASIC-DATA-01`**: the inventory is real data about a private machine and
  is published on purpose; folder and project names are not sample data. The scanner is
  the guard. Review 2027-01-29.

## Not applicable

- Static and read-only: no server, no account, no mutation, no search, no pager.
- No date list and no sorting UI: the project table is sorted by name and the folder
  cards keep the order of `descriptions.json`.
